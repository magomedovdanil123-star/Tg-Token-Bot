ЗАДАЧА: СОЗДАТЬ PER-STOCK SETUP SCANNER

Цель: для КАЖДОЙ акции IMOEX отдельно изучить минимум 1 год истории и найти повторяющиеся внутридневные сетапы, после которых цена с высокой вероятностью проходит +1.5% / +2% в следующие 1–3 торговых дня.

Не создавать одну универсальную стратегию для всех акций.
Каждая акция должна иметь собственный набор исторически подтвержденных сетапов.

1. UNIVERSE

Получить через T-Invest API актуальный состав IMOEX.

Анализировать КАЖДУЮ акцию отдельно.

Не ограничиваться TOP-20.

При изменении состава IMOEX автоматически обновлять Universe.

2. HISTORICAL DATA

Для каждой акции загрузить минимум 1 год истории.

Использовать максимально доступные внутридневные данные.

Основной анализ: 1m / 5m / 15m.

Дополнительно использовать дневные данные для контекста.

3. TARGET

Для каждой точки входа определить:

+1.5% достигнут за 1 торговый день?
+1.5% достигнут за 2 дня?
+1.5% достигнут за 3 дня?

+2% достигнут за 1 день?
+2% достигнут за 2 дня?
+2% достигнут за 3 дня?

Также сохранять:
- максимальный favorable excursion;
- максимальный adverse excursion;
- время до достижения цели;
- максимальную просадку;
- результат сделки.

Не допускать look-ahead bias.

4. АНАЛИЗИРОВАТЬ МАКСИМАЛЬНО МНОГО ФАКТОРОВ

Для каждой исторической точки анализировать:

PRICE ACTION:
- доходность 1/5/15/30/60 минут;
- доходность за день;
- предыдущие 1/3/5 дней;
- ускорение цены;
- импульс;
- локальные максимумы/минимумы;
- пробои;
- ложные пробои;
- консолидации.

TECHNICAL:
- EMA20/50/100/200;
- RSI;
- MACD;
- ATR;
- VWAP;
- Bollinger Bands;
- ADX;
- расстояние до EMA/VWAP;
- положение внутри дневного диапазона.

VOLUME:
- текущий объем;
- средний объем;
- Volume Ratio;
- Z-score объема;
- ускорение объема;
- изменение объема относительно предыдущих свечей;
- аномальный объем.

MARKET CONTEXT:
- IMOEX;
- направление IMOEX;
- доходность IMOEX;
- волатильность IMOEX;
- ширина рынка;
- количество растущих/падающих акций;
- сила движения рынка.

SECTOR:
- доходность сектора;
- сила сектора относительно IMOEX;
- лидеры/аутсайдеры;
- движение других акций сектора.

CROSS-ASSET:
- движение других акций;
- корреляции;
- лидеры и последователи;
- задержка реакции;
- типичные пары/связи.

INTRADAY STRUCTURE:
- время возникновения сетапа;
- открытие;
- первые 15/30/60 минут;
- утренний импульс;
- дневной диапазон;
- положение относительно High/Low дня;
- повторяющиеся временные закономерности.

ORDER BOOK / MARKET DEPTH:
Если T-Invest API предоставляет исторические данные стакана:
- bid/ask;
- spread;
- imbalance;
- глубина;
- изменение bid/ask;
- крупные заявки;
- исчезновение ликвидности;
- давление покупателей/продавцов.

ВАЖНО:
Если исторического стакана через API нет, НЕ придумывать эти данные.
Продолжать анализ без них и явно отметить отсутствие исторического order-book dataset.

5. PATTERN DISCOVERY

Не задавать заранее фиксированный набор сетапов.

Система должна самостоятельно искать комбинации факторов.

Примеры:

объем > среднего
+
IMOEX растет
+
цена выше VWAP
+
EMA20 > EMA50
+
сектор сильнее IMOEX
+
определенное время дня
=
что происходило далее?

Но также искать неожиданные комбинации.

Цель — найти устойчивые повторяющиеся состояния именно для конкретной акции.

6. PER-STOCK MODEL

Для каждой акции создать отдельный профиль:

SBER
LKOH
ROSN
GAZP
NVTK
и т.д.

Например:

LKOH

SETUP #1
Win Rate: 73%
Samples: 842
Target: +1.5%
Horizon: 1–3 days

SETUP #2
Win Rate: 69%
Samples: 1240
Target: +2%
Horizon: 3 days

Не переносить автоматически сетап LKOH на SBER.

Каждый сетап должен иметь свою статистику.

7. STATISTICAL FILTER

Не считать сетап успешным только потому, что исторически он дал 70%.

Минимально требовать достаточную выборку.

Проверять:
- количество случаев;
- Win Rate;
- средний результат;
- медианный результат;
- Profit Factor;
- Expectancy;
- Max Drawdown;
- MAE;
- MFE;
- стабильность по периодам;
- стабильность по годам;
- стабильность внутри разных рыночных режимов.

8. WALK-FORWARD VALIDATION

КРИТИЧЕСКИ ВАЖНО.

Не обучать и проверять закономерность на одной и той же истории.

Разделить данные на:

TRAIN
VALIDATION
OUT-OF-SAMPLE TEST

Дополнительно использовать walk-forward testing.

Сетап считается надежным только если он сохраняет результат на данных, которые не использовались при поиске закономерности.

9. TARGET QUALITY

Искать прежде всего сетапы:

Win Rate >= 65%

Приоритет:
70–75%+

Но НЕ подгонять систему под 70–75%.

Если реальный устойчивый Win Rate только 63% — показать 63%.

Запрещено искусственно повышать показатель путем переоптимизации.

10. REAL-TIME SCANNER

После построения исторической базы запустить real-time scanner.

Каждую минуту:

1. Получить новые данные через T-Invest API.
2. Обновить все акции IMOEX.
3. Рассчитать текущие признаки.
4. Сравнить текущее состояние каждой акции с ее СОБСТВЕННЫМИ историческими сетапами.
5. Найти совпадения.
6. Проверить статистику соответствующего сетапа.
7. Проверить текущий режим IMOEX.
8. Проверить сектор.
9. Проверить объем.
10. Проверить cross-asset подтверждение.
11. Рассчитать вероятность достижения +1.5% / +2%.
12. Рассчитать Confidence.
13. Отсортировать все акции по качеству сетапа.

11. НЕ ДАВАТЬ СИГНАЛ ПО ОДНОМУ ИНДИКАТОРУ

RSI/EMA сами по себе не являются сигналом.

Сигнал появляется только при совпадении исторически подтвержденного набора факторов.

13. RANKING

Каждую минуту анализировать ВСЕ акции IMOEX.

Не показывать 20 случайных акций.

Создать рейтинг:

TOP SETUPS

#1 LKOH — 86
#2 SBER — 82
#3 ROSN — 79
...

Показывать только сетапы, которые прошли статистическую и out-of-sample проверку.

14. DATABASE

Сохранять:

stock_setups
setup_conditions
setup_occurrences
setup_statistics
setup_validation
live_setup_matches
signal_history

Для каждого сетапа хранить полное описание условий, статистику и результаты.

15. НЕ ИСПОЛЬЗОВАТЬ ML НА ПЕРВОМ ЭТАПЕ

Сначала создать качественный dataset и статистический engine.

Не обучать нейросеть ради самой нейросети.

Сначала найти реальные закономерности.

ML можно добавить после формирования надежного dataset.

16. ВАЖНО

Не создавать искусственные данные.

Не создавать фиктивные сигналы.

Не использовать look-ahead bias.

Не использовать будущие значения при формировании текущего сигнала.

Не считать один и тот же эпизод много раз.

Учитывать комиссии и проскальзывание при оценке результата.

Главная цель:

Для КАЖДОЙ акции IMOEX найти ее собственные повторяющиеся внутридневные состояния, после которых исторически с высокой вероятностью происходило движение +1.5% / +2% в горизонте 1–3 торговых дней, затем в реальном времени находить повторение этих состояний и выдавать только статистически подтвержденные сетапы.
