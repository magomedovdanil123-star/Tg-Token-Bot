Не изменяй текущую архитектуру проекта. Нужно значительно улучшить систему поиска сигналов и полностью переработать команду «🔥 Лучшие сигналы».

Главная цель

Когда пользователь нажимает «🔥 Лучшие сигналы», бот не должен читать готовые записи из базы.

Он должен в реальном времени заново проанализировать весь рынок.

То есть:

1. взять все активные акции IMOEX;
2. взять последние свечи;
3. взять все рассчитанные признаки;
4. взять все найденные закономерности;
5. взять все фигуры;
6. взять уровни;
7. взять корреляции;
8. взять рыночный контекст;
9. собрать итоговую оценку каждой акции;
10. отсортировать их;
11. показать только лучшие.

Новое требование

Не использовать фиксированные TP и SL.

Нужно выбирать их автоматически.

Для каждой найденной закономерности искать в истории:

какой Take Profit реально давал максимальную прибыль

и

какой Stop Loss реально минимизировал просадку.

То есть TP и SL должны определяться автоматически на основании исторических результатов.

Например:

для одной акции оптимально

TP 1.8%

SL 0.7%

для другой

TP 0.9%

SL 0.4%

Бот должен использовать именно исторически лучший вариант.

* подтверждение несколькими независимыми факторами.

После этого отсортировать рынок.

Важные требования

* Не использовать заглушки.
* Не генерировать случайные оценки.
* Все значения должны рассчитываться на основе исторических данных проекта.
* Не дублировать одинаковые закономерности.
* Не показывать слабые сигналы (например, Win Rate < 55%, Profit Factor ≤ 1.2, слишком мало наблюдений).
* Если по акции недостаточно подтверждений, не включать её в TOP-5.
* Код должен быть модульным, чтобы в дальнейшем можно было легко подключить новости, фундаментальные показатели и ML-модель без переписывания ядра.
